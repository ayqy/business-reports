# iOS 可行性能力矩阵

快照日期：2026-08-22（Asia/Shanghai）  
目标平台：未越狱、面向普通消费者分发的 iPhone / iOS 26  
原始任务：自动处理知乎恢复前台时的原生开屏广告，以及阻止豆瓣轻微移动触发广告跳转。

## 先给结论

**原生第三方 App 自动跳过：不可行。** 普通 iOS App 没有 Android `AccessibilityService` 的等价公开能力，不能读取并点击另一个 App 的界面，也不能截获另一个 App 进程内的摇动事件。这个判断由 Apple 沙箱、公开 API、容器边界和后台执行规则共同支持。[S24、S26]

**能做的是局部替代，不是 iOS 版李跳跳。** Safari 内容拦截器、系统 DNS、iOS 26 URL Filter 或 VPN 可以挡住一部分网络请求；Voice Control、AssistiveTouch 可以让用户手动发出口令或播放固定手势；快捷指令可以在打开 App 时触发自动化。它们都不能形成“看到第三方原生界面的跳过按钮后自动点击”的闭环。[S27—S34]

## 判定口径

- **等价实现：** 用户打开或切回知乎/豆瓣后，产品无须用户再次操作，就能识别目标 App 当前广告界面并点击“跳过”，或在事件源头阻止摇动触发；只在跳转发生后按预设 App 规则返回不算等价。
- **局部缓解：** 只能减少部分广告资源、绕过部分启动路径、屏蔽部分落地页、在外部 App 误跳后回退、提示用户操作，或由用户主动触发固定点击。
- **消费者可分发：** 不要求越狱、企业 MDM、受监督设备或目标 App 配合，可通过 App Store 或合格地区的替代分发提供给普通用户。

## Apple 官方能力边界

### 直接证据

1. Apple 明确说明所有第三方 App 都在沙箱中，不能收集或修改其他 App 的信息；访问自身以外的信息只能使用 iOS 明确提供的服务。[S24]
2. App Store Review Guidelines 2.5.1 要求只用公开 API；2.5.2 禁止读写指定容器之外的数据；2.5.4 将后台服务限制在系统规定用途。[S26]
3. Safari Content Blocker 的规则由 Safari 执行，能力是隐藏网页元素、阻止浏览器窗口中的资源加载或去除 Cookie。[S27]
4. 快捷指令的 App Trigger 能在“打开/切换到”或“关闭/切离”指定 App 时启动自动化。[S28]
5. Network Extension 可提供 VPN、网络内容过滤和系统 DNS；系统 DNS 配置必须由用户明确启用。[S29、S30]
6. iOS 26 URL Filter 可检查通过 WebKit 与 `URLSession` 发出的完整 URL；其他网络实现只有目标 App 主动接入 Participation API 才会被覆盖。[S31、S32]
7. Voice Control 通过用户说出“Tap …”等命令操作屏幕；AssistiveTouch 可以由用户录制并从菜单播放固定点击或滑动手势。[S33、S34]
8. iOS 内容过滤器、DNS Proxy 的一般部署仍受受监督设备、受管设备或儿童 Screen Time 场景限制；普通消费者可用的 Packet Tunnel、系统 DNS 和 iOS 26 URL Filter 仍然只是网络层能力。[S31]

### 架构推断

- Apple 没有向普通第三方 App 提供可在生产环境查询并操作其他 App UI 的公开服务；结合沙箱与“仅公共 API”规则，无法实现 Android 式跨 App 自动点击。
- 豆瓣的传感器读取与页面跳转发生在豆瓣自己的进程内。第三方 App 既不能插入其事件处理链，也不能替它取消导航。
- 网络层拦截只能决定请求是否完成，不能删除目标 App 自己绘制的开屏容器、倒计时或按钮，也不能在其界面上执行返回或点击。
- 替代商店和 Web Distribution 改变的是安装渠道，不是 iOS 运行时权限；Apple 仍对所有第三方 App 使用沙箱，并对替代分发 App 做平台完整性公证。[S24、S35]

## 路线能力矩阵

| 路线 | Apple 直接提供的能力 | 对知乎开屏 | 对豆瓣摇一摇 | 是否等价自动跳过 | 主要困难 | 证据类型 |
|---|---|---|---|---|---|---|
| 普通 App 跨 App 自动点击 | 无面向消费者 App 的公开跨 App UI 控制服务；第三方 App 受沙箱与容器边界限制 [S24、S26] | 不能读取按钮或代点 | 不能通过读取豆瓣/目标 App 界面决定并代点返回；预设快捷指令回退另见下行 | 否 | 核心 UI 能力不存在 | 官方边界 + 架构推断 |
| Web Clip / 深链启动绕行（开屏弃） | 用 URL Scheme 从新主屏幕图标启动受支持 App；25+ App，1.5 版明确新增知乎 [S39] | 从新图标发起时可能绕过冷启动路径；熄屏直接恢复不会重新触发该入口 | 只能绕过与启动入口绑定的广告路径，不能拦截运行期摇动 | 否 | 用户须改用新图标；URL Scheme 和目标 App 版本会变化 | 厂商官方范围 + 有界推断 |
| Safari Content Blocker | 在 Safari 中按 URL/CSS 规则阻止加载、隐藏网页元素 [S27] | 知乎原生 App 不在覆盖范围 | 豆瓣原生 App 不在覆盖范围 | 否 | 只覆盖 Safari 网页 | 官方直接证据 |
| 系统 DNS（DoH/DoT） | 用户明确启用系统级 DNS 配置 [S30] | 若广告使用独立域名，可能阻断素材；不能点跳过或去掉容器 | 若落地页使用可分离域名，可能阻断加载；不能阻止摇动和导航 | 否 | 只能按主机名；第一方同域、空白容器与误伤 | 官方能力 + 有界推断 |
| 本地 VPN + HTTPS URL 过滤（Jinx 声明） | 商店截图宣称以 DNS、本地 VPN 与本地 MITM 分析可检查的 HTTPS URL [S41] | 命中规则时可能挡素材；不能点跳过或移除容器 | 可能挡落地 URL；不取消摇动和导航 | 否 | 证书锁定、TLS 握手、HTTP/2 等边界由厂商截图直接披露；未真机验证 | 厂商声明 + 有界推断 |
| iOS 26 URL Filter | 过滤 WebKit、`URLSession` 的完整 URL，支持消费者和受管部署 [S31、S32] | 若知乎请求走受支持栈且 URL 可识别，可能挡素材或跳转 | 可尝试挡落地 URL；仍不会取消摇动事件 | 否 | 自定义网络栈需目标 App 主动参与；还需要 PIR 服务与规则维护 | 官方能力 + 有界推断 |
| Packet Tunnel / 本地 VPN | 普通 iOS 可部署 Packet Tunnel Provider [S29、S31] | 可按流量元数据挡部分请求 | 可挡部分网络目标，不能拦截传感器 | 否 | HTTPS/QUIC、同域资源、耗电、误伤、VPN 占位 | 官方能力 + 有界推断 |
| Network Content Filter / DNS Proxy | 网络流量或 DNS 过滤 [S29、S31] | 企业设备可挡部分资源 | 企业设备可挡部分落地请求 | 否 | iOS 普遍要求受监督/受管；消费者场景不成立 | 官方直接证据 |
| Shortcuts App Trigger / 误跳回退（别跳） | 打开/切回指定 App 时运行个人自动化 [S28]；别跳公开说明可在触发后按配置判断是否回到前一 App [S40] | 可提示、记日志或按预设 App 路径回退；不能查询并点击知乎 UI | 若跳往已配置外部 App，可能事后回退；不能截获豆瓣事件或处理原 App 内 WebView | 否 | 需用户安装模板、创建自动化和配置规则；没有跨 App UI 语义 | 官方能力、厂商范围 + 有界推断 |
| ReplayKit + OCR | 用户可录屏/直播屏幕；录制活动须明确同意和可见/可听提示 [S26、S37] | 理论上可识别画面并提醒用户 | 理论上可识别已跳转画面并提醒 | 否 | 需用户启动录制、耗电、隐私敏感，识别后仍不能注入触摸 | 官方能力 + 架构推断 |
| Voice Control | 用户说出命令来点击命名或编号控件 [S33] | 用户可说“Tap Skip”；不是自动 | 用户可口述返回 | 否 | 需主动发声、语言/控件名与环境影响 | 官方直接证据 |
| AssistiveTouch 固定手势 | 用户录制并从菜单播放点击/滑动 [S34] | 可手动播放固定坐标点击 | 可手动播放返回手势 | 否 | 坐标、屏幕尺寸、广告布局变化会失效 | 官方能力 + 有界推断 |
| 关闭目标 App 的 Motion & Fitness 权限 | 用户可在“隐私与安全性”中撤销 App 的运动与健身传感器权限 [S36] | 无影响 | **值得先试：** 若豆瓣依赖受该权限保护的传感器数据，可能阻断；若使用其他摇动事件路径则无效 | 否 | 豆瓣是否列出、当前实现是否依赖该权限尚未真机验证 | 官方能力 + 待验证假设 |
| 替代商店 / Web Distribution | 合格地区可从替代市场或开发者网站安装，仍需 Notarization [S35] | 不增加 UI 权限 | 不增加传感器拦截权限 | 否 | 只改变分发，不改变沙箱 | 官方直接证据 + 架构推断 |
| 越狱 / 私有 API / 注入 | 可绕开正常消费者权限边界 | 工程上可能 Hook UI 或注入点击 | 工程上可能 Hook 传感器或导航 | 接近 | 无法作为正常 App Store 产品，设备基数小、系统升级即易失效 | 工程推断；不作为商业可行路线 |

## 两个原始场景的准确答案

### 知乎：熄屏后切回出现原生开屏广告

**能完整自动跳过吗？不能。** 快捷指令确实能感知“打开或切换到知乎”，但第三方自动化随后没有公开 API 去读取知乎当前按钮、判断是否为广告并代替用户点击。[S24、S26、S28]

可尝试的局部方案：

1. 开屏弃 1.5 明确新增知乎；从其 Web Clip/深链主动启动时可能绕开冷启动广告路径，但熄屏后直接恢复前台没有重新点击新图标，不能视为解决原场景。[S39；后句为运行路径推断]
2. 用 DNS、Packet Tunnel、Jinx 声称的本地过滤或 iOS 26 URL Filter 阻止已确认的广告主机名/URL；成功时可能不下载广告素材或打不开落地页。[S29—S32、S41]
3. 用户启用 Voice Control 后说“Tap Skip”，或用 AssistiveTouch 播放固定坐标手势。[S33、S34]
4. 用 ReplayKit + OCR 只做识别提醒；由于仍不能注入触摸，工程复杂度与用户摩擦明显高于收益。[S26、S37]

这些方案不能保证去掉知乎自己的开屏容器和倒计时。当前没有对知乎 2026-08-22 版本做真机抓包或界面验证，因此“广告请求能否被独立识别”保留为待验证缺口，不能写成已解决。

### 豆瓣：轻微移动触发广告落地页

**能从源头阻止吗？普通第三方 App 不能。** 摇动采集和跳转逻辑属于豆瓣进程，沙箱不允许另一 App 插入其事件处理。[S24、S26；后句为架构推断]

按成本从低到高的可尝试方案：

1. 先到“设置 → 隐私与安全性 → 运动与健身”查看豆瓣；若存在，关闭权限后真机复测。Apple 直接支持撤销此类硬件权限，但豆瓣当前是否依赖它是未知项。[S36]
2. 如果豆瓣跳到已配置的外部 App，别跳的快捷指令流程可能在事后回到原 App；原 App 内 WebView 不一定触发 App 自动化，且摇动已经发生。[S40；覆盖为推断]
3. 用 DNS/Jinx/URL Filter 阻止已识别的落地页请求。即使有效，也只是让目标页加载失败，摇动和页面导航仍然发生。[S30—S32、S41；后句为推断]
4. 用 Voice Control 或 AssistiveTouch 手动返回。[S33、S34]
5. 受监督企业设备可做更严格网络过滤，但依然不能跨 App 自动点击，也不适合消费者小生意。[S31]

## 对商业结论的影响

- **不能把 iOS 用户并入“李跳跳式自动跳过”的可服务市场。** 原报告的海外口径继续限定为 Android，374—382 名月买家门槛不因 iOS 增量而降低。
- **若改做 Safari/DNS/URL 隐私拦截器，已经是另一款产品。** 价值主张从“自动点跳过”变成“网络内容过滤”，竞品、价格、规则、服务器和获客都要重新调研，不能拿本报告的需求与单位经济直接背书。
- **iOS 26 URL Filter 是最值得关注的新能力，但仍不完成原始工作。** 它扩大了消费者网络过滤能力，却不能处理本地渲染广告、倒计时、跨 App 点击或摇动事件。[S31、S32]
- **现有商店产品没有反转权限结论。** 开屏弃、别跳、Jinx 分别验证启动绕行、误跳恢复和网络过滤三条相邻路线；完整产品与广告类型矩阵见 [ios-competitor-functional-matrix.md](ios-competitor-functional-matrix.md)。[S38—S41]
- **越狱路线不构成温饱商业反转条件。** 它同时牺牲普通分发、设备覆盖和持续维护性。

因此，iOS 增量不会反转 no-go，也不会触发完整 PRD。正确的产品边界仍是“Android 静态规则助手”；若单独评估 iOS 网络拦截器，应另立市场假设和证据链。

## 证据边界

### 直接证据

- Apple 沙箱、公开 API、容器和后台执行规则。[S24、S26]
- Safari、Shortcuts、Network Extension、DNS、URL Filter、Voice Control、AssistiveTouch、硬件权限与替代分发的官方能力说明。[S27—S36]
- ReplayKit 的录屏/直播能力与屏幕记录同意规则。[S26、S37]
- Apple Search/Lookup、开屏弃、别跳、Jinx 及海外相邻产品的官方商店字段和厂商公开范围。[S38—S49]

### 推断

- 没有公开跨 App UI 服务，因此不能自动点击知乎。
- 开屏弃从新图标主动启动时可能绕行，但不能覆盖熄屏直接恢复；别跳可能回退外部 App 误跳，但不能处理原 App 内 WebView。
- 网络请求被阻止后，目标 App 仍可能保留空白容器、倒计时或导航状态。
- 替代分发不会解除沙箱；越狱/私有 API 不构成普通消费者商业路线。

### 待真机验证缺口

- 知乎当前 iOS 版本的广告请求域名、URL、网络栈和阻断后的界面表现。
- 豆瓣是否出现在 Motion & Fitness 权限列表、当前摇动实现和关闭权限后的行为。
- 两款 App 对 DNS、iOS 26 URL Filter、VPN 的第一方同域、QUIC、自定义栈与降级策略。

这些缺口只影响“局部网络缓解能覆盖多少”，不影响“普通 App 无法跨 App 自动点击或拦截目标 App 进程内事件”的核心结论。
