# iOS 竞品与自动处理边界矩阵

快照日期：2026-08-22（Asia/Shanghai）

范围：中国区与美国区 App Store；未越狱、面向普通消费者的 iPhone。

数据：Apple 官方 Search/Lookup API 的 8 组关键词检索、12 个 SKU 定点查询，以及厂商在 App Store 页面和官方帮助页公开的功能说明。[S38—S49]

## 结论先行

**有相邻产品，但没有普通 iOS 上等价于李跳跳的产品。** 本轮在中国区检出的最接近产品是“开屏弃”“别跳”和 Jinx：它们分别做深度链接启动绕行、快捷指令触发后的误跳回退、网络请求过滤。三者都不读取第三方 App 的当前界面，也不自动点击“跳过”按钮。[S39—S41；后句结合 S24、S26 为架构判断]

**“自动”有四种完全不同的含义，不能混用：**

1. 开屏弃：用户以后从新 Web Clip 图标启动受支持 App 时，深度链接可能自动绕过原图标触发的冷启动广告路径；不是看到按钮后自动点击。[S39]
2. 别跳：用户安装快捷指令、建立自动化并配置规则后，误跳到指定外部 App 时可触发辅助回退；它明确声明不屏蔽广告、不拦截系统行为。[S40]
3. DNS、VPN、防火墙或 URL 过滤器：一次启用后可自动拒绝命中规则的网络请求；不能操作广告容器、倒计时或按钮。[S41—S48]
4. 李跳跳式跨 App UI 自动点击：本轮没有检出可验证产品，且 Apple 的沙箱与公开 API 边界不提供这条消费者能力。[S24、S26、S38]

因此，准确答案不是“iOS 完全没有去广告工具”，而是“有启动绕行、误跳恢复、Safari 与网络层产品；没有等价的跨 App 自动点击器”。

## 调查方法与证据边界

- 中国区检索词：`自动跳过广告`、`开屏广告`、`李跳跳`、`防误触跳转`；美国区检索词：`skip ads`、`ad skipper`、`system wide ad blocker`、`ad blocker`，每组上限 200 条。
- 冻结结果分别返回 8、176、165、34、142、155、166、162 条；这些是关键词排序结果，包含浏览器、视频播放器、播客和大量无关命中，不是全量市场份额。[S38]
- 对 12 个相关 SKU 另用 Lookup API 定点核验名称、地区、版本、价格、评分、评分数、描述、更新日期和商店链接；结构化原始结果见 `research/data/ios_app_store_snapshot.json` 和 `.csv`。[S38]
- App Store 描述、截图和厂商帮助页能直接证明“厂商公开声称什么”，不能独立证明真实成功率。凡涉及实际拦截效果，均按厂商声明或有界推断标注。
- Apple 消费者商店页和本次官方 API 不公开安装量、MAU、购买数、营收或利润；评分数不能换算成安装量或收入。

## 最接近李跳跳的中国区产品

### 1. 开屏弃：绕过启动路径，不点击广告

官方商店说明与帮助页一致：它为 25+ 常用 App 生成主屏幕 Web Clip，用 URL Scheme 深度链接启动目标 App；用户必须以后使用新图标而不是原图标。其 1.5 版更新说明明确新增“央视频、知乎、浙里办”。商店截图可见的示例还包括淘宝、天猫、京东、美团、爱奇艺、今日头条、哔哩哔哩、搜狐视频、腾讯视频和网易新闻。[S39]

它能自动处理的是：

- **支持 App 经新图标发起的部分冷启动开屏/摇一摇启动路径**；原理是换入口，效果依赖目标 App 的 URL Scheme 与版本。[S39]
- **知乎从 Web Clip 主动启动的场景**已有版本说明支持信号；但没有公开成功率或当前版本真机结果。[S39]

它不能处理的是：

- 信息流广告、视频中插、网络广告，以及 App 已经打开后的广告；厂商明确写明这些不在范围内。[S39]
- 熄屏后直接回到仍在前台的知乎：此时没有重新点击 Web Clip，不能假定深链绕行会执行。
- 豆瓣运行期间轻微移动触发的事件：它没有传感器拦截能力；公开列表也没有足够证据确认豆瓣适配。
- 任意广告的“跳过”按钮：它根本不读取或点击第三方 UI。

### 2. 别跳：误跳后的自动回退，不跳过广告

官方描述明确说明它基于 iOS 快捷指令与自动化：用户手动安装模板、选择触发 App、配置规则；系统触发并打开别跳后，别跳在本地判断是否需要回到前一个 App。它同时明确声明“不修改其他应用、不屏蔽广告、不拦截系统行为”。[S40]

它能自动处理的是：

- **已配置的 App 间误跳**：若摇一摇把用户带到一个可由“App 已打开”自动化识别的外部 App，规则可尝试把用户带回去。[S40；具体覆盖为有界推断]

它不能处理的是：

- 原 App 内部 WebView、内嵌落地页或没有切换 App 的导航。
- 区分每一次“用户主动打开”和“广告误触”的完整语义；需依赖用户配置与触发上下文。
- 消除原广告、阻止摇动事件、点击跳过按钮。

### 3. Jinx：DNS/本地 VPN/HTTPS URL 过滤，不操作界面

Jinx 的商店描述宣称覆盖网页与 App，过滤 Banner、插屏、信息流和追踪器，并披露 2 元/月自动续费。商店截图进一步显示两层机制：默认以本地 VPN 做 DNS 域名过滤；“深度拦截”模式宣称用本地 MITM 代理分析 HTTPS URL，并明确列出证书锁定导致 TLS 握手失败、仅支持 HTTP/1.1 而不能检查 HTTP/2 的限制。[S41]

它能自动处理的是：

- 命中域名黑名单的广告/追踪请求；如果广告使用独立域名，可能覆盖第三方 App。[S41]
- 在用户安装相应证书且流量可解密、无证书锁定、协议受支持时，命中 URL 黑名单的 HTTPS 请求。[S41；效果是厂商声明，未做真机复验]

它不能处理的是：

- 目标 App 本地绘制的开屏容器、倒计时、原生按钮或摇动事件。
- 证书锁定、HTTP/2/其他不受支持协议、第一方同域且未命中 URL 规则的请求；厂商截图已直接暴露部分失败边界。[S41]
- 在阻断请求后保证界面消失；目标 App 仍可能展示空白、重试、倒计时或降级素材（架构推断）。

## 到底能自动跳过哪些广告

| 广告形态 | 普通 iOS 可实现程度 | 可行产品路线 | 不能承诺的部分 |
|---|---|---|---|
| Safari 网页横幅、弹窗、遮罩、追踪脚本 | **高**：可在加载前阻止资源并用 CSS 隐藏元素 | AdGuard、1Blocker、Wipr 2、AdBlock Pro、AdBlock | 仅限 Safari/受支持网页；反拦截与第一方脚本仍可能漏网 |
| 使用独立广告域名的 App Banner/插屏/追踪器 | **中**：域名规则命中后可后台自动拒绝请求 | Jinx、AdGuard DNS、Lockdown、Blokada、NextDNS、AdBlock、Wipr Filtr | 可能留下空白/倒计时；同域、缓存或本地素材无法按域名区分 |
| HTTPS 中可区分路径的原生广告请求 | **低至中**：需要 URL Filter 或可检查流量；具体覆盖依赖协议与证书 | Jinx 深度拦截的厂商声明；iOS 26 URL Filter 路线 | 证书锁定、自定义网络栈、HTTP/2/QUIC、目标 App 对抗与误伤 |
| 从原图标触发的冷启动开屏/摇一摇启动页 | **局部**：可换深链启动入口绕行 | 开屏弃 | 只覆盖受支持 App 与启动入口；不处理恢复前台或运行期广告 |
| 摇一摇后跳到另一个已配置 App | **局部**：跳转发生后再自动回退 | 别跳 | 不能阻止摇动；原 App 内 WebView/落地页不一定触发 App 自动化 |
| 原生界面中的“跳过/关闭”按钮、倒计时 | **不可等价实现** | 无普通消费者 App 路线 | 没有跨 App UI 读取与触摸注入公开 API |
| 原生信息流同域广告、YouTube/视频 App 内同源广告 | **通常不可可靠区分** | 只能改用 Safari/第三方播放器，或依赖服务特定规则 | DNS 可能把内容一起误伤；第三方播放器只清理自身容器，不是系统级跳过 |
| 豆瓣进程内的摇动事件 | **不可由第三方 App 截获** | 用户关闭相关权限（若存在）或目标 App 自身设置 | 网络过滤最多阻断落地请求，不取消摇动和导航 |

## 对知乎与豆瓣的直接回答

### 知乎熄屏后恢复前台

- **没有产品能看到知乎的跳过按钮并自动点击。**
- 开屏弃 1.5 的确公开写了“新增知乎”，但它只在用户通过 Web Clip/深链重新启动时换入口；熄屏后直接恢复前台没有这个动作，因此不能把“支持知乎”外推成解决原场景。[S39；后句为运行路径推断]
- Jinx/DNS/VPN 类产品可能挡掉可分离的广告请求；是否留下空白、倒计时或被知乎改走其他域名，仍需当前版本真机验证。[S41—S48；效果为推断]

### 豆瓣轻微移动触发广告跳转

- **没有产品能拦截豆瓣进程内的摇动事件。**
- 若豆瓣把用户跳到淘宝、京东等外部 App，别跳的快捷指令规则可能在跳转后把用户送回；这属于事后恢复，不是阻止误触，且需要用户预先配置。[S40；覆盖为推断]
- 若落地请求域名可识别，Jinx/NextDNS/Blokada 等可能让页面加载失败；导航动作本身仍会发生。
- 开屏弃只针对启动路径，且现有公开证据不足以确认豆瓣适配；不能把它写成豆瓣运行期解法。

## 市场信号如何解读

- 中国区三个近邻产品的评分数为 15、102、1,626；这证明已有开发者在尝试“启动绕行—误跳恢复—网络过滤”三条产品路线，但不能证明安装规模或收入。[S38—S41]
- 成熟海外 Safari/DNS 产品的评分数从 1,273 到 72,327 不等，说明 iOS 广告/隐私工具存在长期需求；需求主要落在 Apple 允许的 Safari 与网络层，而不是跨 App 自动点击。[S42—S49；后句为分类归纳]
- 直接近邻的开屏弃、别跳均为免费；Jinx 公开价格只有 2 元/月。即使忽略合规，现有信号也没有为原方案提供比 Android 样本更强的“稳定月入一万元”付费证据。
- Apple 不公开安装量、购买数、营收和利润，本报告没有用评分数伪造下载量或收入。由此只能判断“有产品、有需求”，不能判断“已有成功温饱样本”。

## scan 三桶结论

### 官方直接证据

- Apple 官方 Search/Lookup API 返回的关键词结果与 12 个 SKU 商店字段。[S38]
- 开屏弃、别跳、Jinx 的 App Store 描述、更新说明、商店截图，以及开屏弃官方帮助页。[S39—S41]
- 海外产品的官方 App Store 页面和厂商公开功能边界。[S42—S49]
- Apple 沙箱、公开 API、Safari、Shortcuts、DNS、Network Extension 与 URL Filter 边界。[S24、S26—S32]

### 基于证据的推断

- 关键词样本没有检出跨 App 自动点击产品，与 Apple 平台权限边界相互印证；因此普通消费者市场不存在可验证的等价李跳跳路线。
- DNS/URL 被阻止后，目标 App 可能保留空白容器、倒计时、导航或改走备用请求。
- 别跳可能缓解“摇一摇跳到外部 App”，但无法覆盖 App 内 WebView。

### 待真机验证缺口

- 开屏弃 1.5 对知乎当前版本的真实成功率，以及熄屏恢复、冷启动、热启动之间的差异。
- 豆瓣是否出现在开屏弃支持清单；别跳对豆瓣到具体广告目标 App 的自动回退链路。
- Jinx 的证书安装流程、MITM/HTTP 版本实际覆盖、知乎/豆瓣规则命中、误伤与阻断后 UI。
- 各 DNS/VPN 产品对知乎/豆瓣当前域名、同域资源、QUIC、自定义网络栈和降级策略的覆盖。

这些缺口影响“局部缓解的实际覆盖率”，不影响“没有公开跨 App UI 自动点击能力”的核心结论，也不反转原商业 no-go，因此完整 PRD 条件仍未触发。
