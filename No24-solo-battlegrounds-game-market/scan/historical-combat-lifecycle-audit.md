# 2019 上线周：招募结束至伤害淘汰的参考状态转换

**目标**：构建 `15.6.0.35747` 上线周历史研究支线；核验日为 2026 年 9 月 26 日（北京时间）。[配置](historical-combat-lifecycle.json)、[基础 30 个向量](historical-combat-lifecycle-vectors.json)、[玛尔加尼斯免疫边界 17 个增量向量](historical-hero-immunity-audit.md)与[运行器](verify_historical_combat_lifecycle.py)提供可执行的**阶段衔接与结算合同**。[有界逐次战斗执行器](historical-combat-event-audit.md)现在可为部分卡牌组合提供终局存活实例；本转换器仍不模拟攻击、亡语及随机效果，也不宣称原版服务端重放。

### 用户故事：结束招募并看见可解释的结算

- 代表用户：一局单人酒馆玩法中的玩家。
- 场景：确认站位，结束当前招募轮。[H01]
- 目标：观看自动战斗，知道生命为何变化，以及是否还能进入下轮。[H01]
- 成功结果：平局不扣生命；胜负时可从酒馆等级和存活随从等级复算伤害；生命归零后不再参与招募。[H01][H03]
- 推断步骤：配对对象、代理快照版本及相同轮次多个淘汰者的名次裁决没有首版直接证据，本参考实现由调用方提供配对并将并列名次记 `unknown`。

### 动线：招募锁定→战斗快照→外部战斗结果→淘汰或继续

1. `end_recruit`：每位仍存活的玩家依次锁定本轮阵容；有未领取三合一发现时拒绝。**阶段切换来自 [H01]；锁定门槛是 `[R]`。**
2. `begin_combat`：调用方注入覆盖所有存活席位且互不重复的配对；存活人数为奇数时，一组使用已淘汰席位的阵容快照。复制双方酒馆等级与场上实例，不写回招募阵容。**代理机制来自 [H03]；配对算法与复制时点是 `[R]`。**
3. 外部战斗引擎按[历史战斗参考顺序](historical-2019-mechanics.md#52-可执行的确定性参考顺序-r)产生终局存活实例，并提交 `settle_combat`。本合同校验实例必须出自战前阵容或带来源实例的生成清单；动态生成的 81 卡候选明确标 `reference_injected`。玛尔加尼斯英雄免疫只按终局存活实例参考求值，不能从保留的招募阵容或调用方伪造标记借用，详见[阶段边界审查](historical-hero-immunity-audit.md)。**输入不等于原版实测**。
4. 结算器由存活实例与快照自动推得胜负及伤害；平局为零，代理获胜可扣活人生命，活人击败代理不扣代理生命。同轮全部配对先结算，再更新生命与淘汰。**伤害公式与代理能力据 [H03]；事务顺序为 `[R]`。**
5. 若仅一人存活，写 `winner_id` 并停止；否则 `open_next_recruit` 清除本次战斗快照，向每名活人发 `advance_recruit` 钩子。**直到一人存活来自 [H01]；进入下一轮时商店、金币及折扣仍由[招募转换器](historical-recruitment-transition-audit.md)处理。**

## 类型、前置和不变量 `[R]`

| 结构 | 字段与检查 |
|---|---|
| `Seat` | `seat_id/health/tier/alive/ready/board/pending_rewards`；生命 `>0` 与 `alive` 一致，场上最多 7 张。来自招募转换器的 `normal_id` 接线时映射为本合同的 `card_id`。 |
| `BoardInstance` | `instance_id/card_id`；研究表中的卡由[81 卡表](historical-card-pool.json)推得酒馆等级。招募中已有的衍生物必须带 `origin=recruit_token`、外部指定的 `damage_tier` 与 `tier_grade=reference_injected`。 |
| `Pairing` | `pair_id/left/right`；`right` 可是活人席位或 `{ghost_of: 淘汰席位}`。八席或剩余席位每人恰好出现一次；奇数时恰好一组代理。**真实配对策略未知，调用方注入不能标为原版随机。** |
| `CombatSnapshot` | 深拷贝配对双方的酒馆等级与阵容。死亡、战斗受伤、战斗生成单位均不写回招募阵容。 |
| `CombatResult` | 每组的 `left_survivors/right_survivors` 是实例 ID；`generated` 清单列 `instance_id/card_id/origin/source_instance_id`，跨侧召唤还列 `source_side`。已知固定衍生物的伤害等级由调用方以 `reference_injected` 标记；由随机效果生成的研究表卡另标 `pool_grade=reference_injected`，不能证明原版生成资格。 |
| `History` | 记录每组胜负、伤害、受伤者及本轮淘汰者；同轮多人淘汰的 `placement` 固定 `unknown`，不按本地数组顺序虚构原版名次。 |
| `HeroImmunity` | 招募中按本方当前战场是否有玛尔加尼斯判定；终局按实际存活实例判定。只编译愤怒编织者的 1 点招募自伤；其触发必须带 `reference_injected`，其他自伤/生命支付尚未泛化。原版阶段时点为 `unknown`，见[节点和验收](historical-hero-immunity-audit.md)。 |

每个动作复制状态、验证全部输入、成功才提交。错误配对、伪造存活实例、双边都仍存活的非终局结果、无来源临时单位、缺证据等级及错阶段操作必须保留原状态和动作。`exact_2019` 请求被拒绝，直到存在足以核定配对、候选与同刻事件的同构建直证。[30 个向量](historical-combat-lifecycle-vectors.json)覆盖这些拒绝、八人快照、伤害计算 `4+2+5=11`、代理获胜、两人同时出局、召唤物与商店卡同 ID 时的实例区分、对手侧召唤及下轮恢复。
