## 交叉检查与反证

1. H03 表逐阶有 **12、16、17、14、13、9** 个条目，合计 81 个不同普通 ID；H04 中 81 个 ID 都存在。H04 也存在一些历史表没有列入的素材，例如金色 `Safeguard`，故“客户端有素材”不等于“商店可购买”。
2. 81 张里，H04 有 68 个可按同名与身材匹配的独立 `TB_BaconUps_*` 金色定义；其中文名称与普通卡一致，基础攻/生均为普通卡的 2 倍。其余 **13 张缺对应的独立金色三合一条目**：正义保护者、虚空行者、粗俗的矮劣魔、梦魇融合怪、吵吵机器人、护盾机器人、钴制卫士、闹闹机器人、洞穴多头蛇、毒鳍鱼人、死神4000型、扎普·斯里维克、迈克斯纳。注意 H04 另含 `PREMIUM=1` 的 `TB_BaconUps_059t` **2/6 金色虚空行者实体**；其 ID/卡面与金色虚空领主的召唤物吻合，但缺实际生成链直证，更不能反推商店虚空行者三合一的实体 ID。逐卡表对 13 张整体保留**推断**标记；H16 对金色扎普旧风怒提供官方追溯，H17 对粗俗的矮劣魔提供稍后社区旁证，详见[逐项审查](historical-golden-gap-audit.md)。
3. H03 的“中立”是历史表的**展示分栏**。H04 给梦魇融合怪的种族标记是 `ALL`；它在玩法上按所有种族处理。机械的客户端枚举名是 `MECHANICAL`，不能因标签拼写不同就误判为不一致。
4. H04 与 H05同源于游戏资源提取，交叉核对只能发现映射或解析错误，不能充当两家独立运营数据。H03 的日期晚于 H02 四天；若要追求“11 月 5 日当天可抽取概率和精确英雄开关”，仍需可重放历史客户端与服务端证据。
5. `[C]` H04 的 `TB_BaconShopTechUp02_Button` 至 `06_Button` 依次给出 `COST=5/7/8/9/11`，H05 的同构建按钮条目交叉一致。原规格把末档写成 10 是错误；按钮上的基础 `COST` 也不能证明所有折扣叠加顺序。H01 只直接证明“不升级则下轮降 1”。
6. `[O+C→I]` H01 首发 **24** 人；H04/H05 有 28 个编号玩家英雄资源，另有不参与选择的鲍勃、克尔苏加德代理与占位资源；H06 指明其中四名于北京时间 2019 年 11 月 20 日公告加入。做集合差得到[推定首发 24 人](historical-hero-candidates.md)，且 H06 明示首发名单中的四人后来轮出，H08 对疯狂金字塔提供追加旁证。这是**计数与轮换证据支持的强推断**，不是服务端开关清单或每局候选概率的直接导出。
7. `[W/I]` H07 提供的库存 18/15/13/11/9/6 和明确展示位 3/4/4/5/?/6，可用作上线周参考；第 5 级仍展示 5 位是连续等级不改变位数的**推断**，配置记为 3/4/4/5/5/6。其发表与修改晚于 H02，故不写成首发当日服务端已证实。H07 的返池文字和非商店生成特例也只是当时玩家观察，尚无服务器代码核验。
8. `[H09+C→对照]` H09 的商店随从表与 H03 的 81 个 ID 经 H05 英文名称映射后**集合一致**，但 H09 没写构建号。五个动态数组分别有 9/10/14/22/12 项；与[先前的客户端标签筛选](historical-random-pool-candidates.json)相比，模拟器的原卡费用 1/2/4 池多出 2/1/2 个构建内 `BGS_*` 实体，传说池少了卡德加与比斯巨兽，亡语池恰好一致。完整逐 ID 对照保存在[同期模拟器候选集](historical-community-simulator-pools.json)。这证明**两种研究方法给出的候选名单并不相同**，不能择一冒充服务端真值。
9. `[H09]` 候选池通过写死数组和 `std::rand()%数组长度` 抽索引；`battle.cpp` 先逐目标处理顺劈伤害、再让主目标反击，`check_for_deaths()` 清掉双方本批死亡单位后按战场数组的第 0 方到第 1 方结算，`on_death()` 先亡语再友方死亡触发，召唤时立即触发友方召唤事件。它是一套可复核的**社区实现顺序**，不是 2019 服务端规则。同一提交中始祖龟执盾者和扎普的基础数值仍填 0/0，老瞎眼光环处写明 `TODO: this is incorrect`；这进一步限制了它的精度。
10. `[H10+H09→有限交叉验证]` Old Guardian 的同期作者说明与独立模拟器均给出“斯尼德传说候选 **12**”的数量；H05 仅按传说标签筛出 **14**。两种社区材料彼此独立，因而可把“同期口径为 12”列为**有交叉支撑的二手判断**；作者说明没有列 ID，不能用它证实 H09 恰好排除的卡德加和比斯巨兽，也不能升级为暴雪服务端直证。H11—H13 的页面元数据和本轮 `LOGIN_REQUIRED` 获取结果见[原版录像/战报核验](historical-replay-audit.md)；七个争议 ID 与事件顺序仍为 `unknown`。
11. `[H14/H15→原版画面直证，但命题不同]` H14 的原始文件已完整下载并与档案哈希核对；H15 的 `01:01:54–01:01:58` 连续画面直接显示斯尼德作为六星**发现选项**，玩家选择了扎普。这个实见记录不能被转写为“斯尼德亡语抽到某传说”。两段画面都未显示可确认的客户端构建号；七个争议 ID 的**动态召唤资格**及同刻死亡优先级仍为 `unknown`，见[逐项取证](historical-replay-audit.md)。
