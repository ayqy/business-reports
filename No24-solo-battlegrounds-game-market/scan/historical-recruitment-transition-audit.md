## 状态及动作合同 `[R]`

状态的 `phase` 固定为 `recruit`；`round/tier/coins/skipped_rounds/hero_discount/upgraded_this_round` 描述经济，`hand/board/shop` 存具体实例，`pending_rewards` 存未领取发现，`serial` 给参考实例生成稳定 ID。`shop` 元素带 `slot` 和 `frozen`；购买后留下空位。手场个体按 `normal_id` 判断同定义，不能用本地化名称；独立金色实体使用客户端 `golden_id`，缺少实体的 13 张仅使用 `reference:<normal_id>:golden` 身份键。泽鲁斯、蛮鱼斥候、温顺的巨壳龙、寒光先知和石塘猎人已在本招募执行器中处理有界金色分支；其余金色效果仍见[逐卡效果节点](historical-effect-node-audit.md)。

每个动作先复制并校验状态，成功才提交；金币不足、容量满、错误选择或注入候选非法时返回错误码，**原状态和注入动作完整保留**。候选由调用方显式注入：商店只检查 81 张研究表成员与酒馆上限；三合一发现要求三张互异且恰为奖励等级；蛮鱼斥候发现另用九项分级研究索引；巨壳龙进化使用十个已核卡面实体的参考索引。该检查只证明向量内的**参考资格**，不证明暴雪服务端的真实候选、共享库存或均匀抽取。执行器不取随机数，不更改共享库存；除已编译的泽鲁斯手牌变形、蛮鱼斥候发现、巨壳龙进化、寒光先知生命强化和石塘猎人指定强化外，其余卡牌和英雄效果只输出供其他节点接线的事件钩子。巨壳龙七种非数值效果已有[有界战斗接线](historical-combat-adapt-audit.md)；寒光先知的永久生命增量已有[战斗快照贯通](historical-recruitment-coldlight-audit.md)，石塘猎人的永久攻生增量已有[指定目标贯通](historical-recruitment-rockpool-audit.md)；同刻事件优先级仍为 `unknown`。

| 转换 | 前置与状态变化 | 边界向量 |
|---|---|---|
| `buy` | 查商店实例、校验 3 金与手牌空间，移至手牌；若新得个体凑足三张同定义普通卡，自动合成一次。 | RT-01—03、RT-19 |
| `sell` | 只能选场上实例，移除并得 1 金；参考金币上限为 10。 | RT-04—06 |
| `refresh` | 扣 1 金，保留冻结实例和原展示位，外部候选填满空位与未冻结位。 | RT-07—10、RT-29—30 |
| `freeze` | 免费将当前展示全部冻结；再次切换则全部取消；混合状态点击时全部冻结。 | RT-11—12 |
| `upgrade` | 按 `max(0, 基础价−未升级轮数−英雄折扣)` 计价；成功升级并清空折扣，不自动刷新当前商店。 | RT-13—16 |
| `resolve_triple` | 跨场上、手牌按**场上再手牌**选三张，求和永久攻生加成与附着，合为一张金色手牌卡；此顺序仅是确定性参考。 | RT-17—19、RT-31—32，另对 13 张缺独立金色 ID 做逐张身份回归 |
| `play` | 手牌卡按指定位置入场，场上最多 7；首次打出带待奖励标记的金色卡才入队一次发现；蛮鱼斥候普通／金色每遍发现一／两张，单一布莱恩参考分支组合成 2／3／4／6 次逐次发现；巨壳龙把一／两次注入的进化选择作用于当时的己方鱼人快照；寒光先知对除自身外的鱼人永久加生命，单一布莱恩参考重复二／三遍；石塘猎人逐遍指定一名场上其他鱼人永久加攻生，单一布莱恩参考重复二／三遍。 | RT-20、RT-27—28；RM-01—32；RA-01—36；RC-01—13；RP-01—19 |
| `triple_discover` | 奖励目标等级 `min(6, 打出时酒馆等级+1)`；调用方注入三选项，玩家选中其一入手牌。 | RT-21—24 |
| `advance_round` | 冻结位保留一次并解冻，其余位由外部注入；金币重置为 `min(10, 新轮数+2)`，未升级则参考折扣计数加 1；手中泽鲁斯来源实例在参考时点按显式索引变形。 | RT-25—26；RZ-01—11、13—15 |
| `buy` + 变形来源 | 购入第三张普通同定义卡若需消耗仍在手中的变形泽鲁斯，则拒绝无法核实的合成时序。 | RZ-12 |

**不能推断为原版事实的细节**：金币售出上限、手牌满时即使三合一可腾位也先拒绝购买、冻结中间展示位的保位算法、折扣消耗顺序、附着串接顺序、发现恰有三张互异定义、奖励排队时点、第三张由发现获得时的自动合成，以及蛮鱼斥候双次发现与巨壳龙双次进化的选项、顺序和缺口处理，均是本套 `[R]` 决策。后续若有同构建可重放证据，须改配置与向量并保留原结论差异；不能悄悄把这些规则标作 `[O]` 或 `[C]`。

运行 `python3 scan/verify_historical_recruitment_transitions.py` 可核对 147 个动作场景及 13 个缺独立金色实体的形式键；其中的失败场景同时断言状态与输入动作没有变化。泽鲁斯的 80 项参考索引及金色缺口见[专项审查](historical-recruitment-zerus-audit.md)；蛮鱼斥候的九项研究索引及布莱恩重复发现边界见[发现审查](historical-recruitment-murloc-audit.md)和[布莱恩专项审查](historical-recruitment-murloc-brann-audit.md)；巨壳龙十项选项与非数值战斗接线边界见[进化审查](historical-recruitment-adapt-audit.md)，单一布莱恩的进化组合次数另见[专项审查](historical-recruitment-adapt-brann-audit.md)；寒光先知的“其他鱼人”目标、重复数值及战斗快照见[生命强化审查](historical-recruitment-coldlight-audit.md)；石塘猎人的目标合法性、布莱恩逐遍选择与攻生快照见[指定目标审查](historical-recruitment-rockpool-audit.md)。验证只证明这份参考合同自洽，不等于原版端到端验证。[H01—H07 的精确出处](historical-evidence.md)。
