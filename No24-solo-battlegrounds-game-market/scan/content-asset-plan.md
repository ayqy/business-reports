# 内容与素材制作规格：历史索引、原创产线与验收

核验日：2026 年 9 月 25 日（北京时间）。这份文件把“完整内容”拆为**可核对的历史数据**和**待原创制作的可发布素材**。前者的 81 个研究实体、金色变体及 16 组固定召唤物已经逐项落在[卡表](historical-card-pool.md)、[结构化索引](historical-card-pool.json)、[召唤物表](historical-token-pool.md)；后者是制作需求，**没有现成原画或授权文件**，不能称为已完成素材包。

## 1. 每卡条目与文件槽

`historical-card-pool.json` 的每条记录都有稳定 `reference_art_slot=H2019-001…H2019-081`，并完整绑定历史普通 ID、金色 ID 或“无独立金色实体”、名称、等级、实际种族、普通/金色攻生和机制摘要。这个键只用于索引历史研究；制作中必须另建 `original_unit_id`，避免程序把原作 ID、原作名称或玩家外号直接显示给公开用户。

每个**原创**单位定义的强制字段：

| 字段 | 内容与校验 |
|---|---|
| `original_unit_id`, `version`, `locale` | 不含原作 ID；ID 一旦发布不得因改名复用。 |
| `display_name`, `visual_hook`, `silhouette`, `palette`, `props` | 独立世界观名称与可画的视觉描述；视觉轮廓、主色和识别道具须通过相似性检查。粉丝外号不能未经审查直接转正为卡名。 |
| `tier`, `tribe_tags`, `base_attack`, `base_health`, `normal_effect_ast`, `gold_effect_ast` | 普通与金色都给结构化事件节点、合法目标、次数、持续时间、随机池和满格行为，不从中文文案运行时推导。 |
| `normal_text_zh`, `gold_text_zh`, `keywords`, `help_text_zh` | 提供玩家可读的原创文案，并由 AST 生成或校验数值；文字长短经 iPhone 横屏卡片测量。 |
| `portrait_asset`, `gold_variant_asset`, `combat_sprite`, `icon_assets`, `vfx_ids`, `sfx_ids` | 每个字段指向存在的资源；金色可以共用原创人物肖像，但必须有可识别的金色边框与动效，不能复用他人原画。 |
| `artist`, `creation_record`, `license_scope`, `similarity_review_id` | 记录作者、制作草图/工程文件、使用地域/媒介/期限/改编许可、独立审查结论；不全则不能进入可发布内容包。 |

**推荐制作尺度 `[P]`**：原画母版 1024×1024 px，战斗单位透明图 512×512 px，图鉴缩略图 256×256 px，48/96 px 关键词图标；留 15% 安全裁切区，普通与金色卡在灰度、色弱模式均能区分。横屏 iPhone 至少用一台小屏和一台标准屏查看全名、能力、数字和特效遮挡。尺寸是本品制作建议，不是暴雪素材规范。

**一张卡的交付包 `[P]`**：一张原创 Q 版角色肖像、金色表现层、战斗透明角色、选中/受击/死亡状态、玩法关键词图标引用、可放大的卡面文案、必要的出场/攻击/亡语/召唤特效，以及版本化元数据。角色和宠物、怪物、机械统一遵循星港工坊的原创线条、比例、光照与音色手册；不可把历史卡的姿态、轮廓、配色、标志、构图换成 Q 比例就称原创。

## 2. 召唤物与动态池素材

[16 组固定召唤物](historical-token-pool.md)至少需要各自独立的图像槽、种族标签和普通/强化数值。即使同名，历史上商店卡与衍生实体也可共用定义 ID 或拥有不同 ID；运行时实例必须区分 `source_instance_id`。授权复刻支线的同名金色效果见逐卡表，不得只把普通图放大。

载人收割机、载人飞天魔像、骑乘迅猛龙、阴森巨蟒、斯尼德的伐木机、百变泽鲁斯及坎格尔的学徒会从动态候选池或本场死亡记录产出单位。**资产数量上限不等于 81 + 16**：这些动态卡可能生成历史池外实体。精确复刻的 `summon_pool_ids` 尚无完备历史服务端记录，所以可执行原型须将其配置为受限、明确列出的测试池，并标 `historical_unverified=true`；正式历史精确复刻验收前需补齐完整候选、排除规则与对应素材，不得以 2026 年资料臆填。

## 3. 原创 Q 版路线与历史研究路线的交接

| 路线 | 内容与素材的可实施程度 | 发布状态 |
|---|---|---|
| **历史研究/授权复刻** | 81 张及金色数值与效果索引已具备，16 组固定召唤物具备；事件队列有可执行参考算法，少数金色变体、动态随机池和服务端先后手仍须历史实机验证。若取得许可，方可按授权范围制作卡面、名称、音效和营销材料。 | 不能因规格完成就推定获得暴雪许可。 |
| **原创星港工坊** | 主规格定义全本机 AI、短局存档、六格布阵、蓝图、买卖与票券流程；**其原创 40 单位完整内容表尚未被本次历史索引替代**。在公开构建前要逐卡原创命名、原创能力组合与美术设计，再验证 40 单位的玩法闭环。 | 通过权利审查、发行与中国区审批门禁后才可申请上架。 |

**设计交接检查 `[P]`**：① 每条卡定义可按 ID 找到全部普通/金色规则；② 全部效果节点均有合法目标、满格、空池及随机回退；③ 每个 `summon_token_id` 存在对应资源；④ 普通与金色中文文案和引擎参数一致；⑤ 人物草图、肖像、动画、声音及许可证链完整；⑥ 每张卡在 iPhone 图鉴、招募、战斗、战报四处可读；⑦ 相似性审查覆盖单卡与整体卡池编排。未通过者仅可保留在内部研究包，不进入可发布包。

## 4. 样板资产验收用例

| 编号 | 检查 | 结果 |
|---|---|---|
| AS-01 | 任抽 10 个 `H2019-*` 研究槽，查 JSON 与 Markdown 的 ID、等级、普通/金色数值和证据标记 | 内容一致；历史槽不能被当作公开资源路径。 |
| AS-02 | 源卡召出固定 token，检查 Token ID、基础数值、种族与金色变化 | 与[召唤物表](historical-token-pool.md)一致；满格无溢出。 |
| AS-03 | 动态召唤卡触发且历史池未配置 | 程序产生可诊断的配置错误，不擅自选择现行版单位。 |
| AS-04 | 公开构建扫描全部可见卡片及元数据 | 不出现历史原作 ID、名称/外号、原画或未许可的整组复刻数值。 |
| AS-05 | 色弱模式、设备字体放大与横屏小屏查看普通/金色卡 | 图标/名称/关键词不靠颜色单独区分且不截断关键数值。 |
