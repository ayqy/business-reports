## 2. 产品定义、范围和成功条件

**暂名“星港工坊”**仅作工作代号，不作为已清查商标的正式名称。`[P]` 主题为“在移动工坊招募原创机械生物，选择航线蓝图，排布两排队形，与本机领航员决出名次”；独立视觉语言、文本和单位特效由内容门禁另行确认。`[U]` 核心价值是没有匹配等待、局中可暂停、能在短时间获得组队成长与复盘感。`[I]` 公开评论中存在希望保留单机体验的具体表述，但无法推出该新作的转化率。[S07]

**产品边界 `[P]`：** 首发仅 iPhone 横屏；一人加七名 AI，全部对局计算、战斗、存档在设备上完成。无账号、实时联机、排行榜、广告 SDK、云存档或真人匹配。首次安装有完整免费对局；已验证购票权益可离线使用；新购、恢复购买需要可访问 App Store。年龄分级、语言、设备最低要求在上架提交前以内容审查与实际性能决定，不从竞品版本抄取。

**可观察产品指标 `[P]`，均为内部测试目标而非市场事实：** 新手在不看外部攻略下完成第一局；常规单局目标 10—18 分钟，可在任意决策节点安全退出；重复同一种子与同一操作序列得到相同结果；P0 崩溃不丢失最近一次已确认操作；付费不会阻断免费玩家正常完成局。商业成败另按[市场模型](../research/model-results.json)及真实付费、续费和获客数据决定，规格的完成不自动满足月入一万元。

**故事 ST-01｜碎片时间首玩。** 代表用户：没时间排真人局、但喜欢阵容成长的玩家。`[D]` 暴雪官方描述“英雄—招募—战斗”循环；《月圆之夜》近期中国区评论存在“单机”诉求。[S01][S07] `[I]` 此人可能偏好短局与可中断；尚无本品访谈证据。`[P]` 从首页点“开始”，不登录、无付费提示前完成互动教程并看见首轮自动战斗结果；价值是即时理解决策影响。

**故事 ST-02｜反复构筑。** 代表用户：想尝试不同单位组合的回访者。`[D]` 参照玩法有升级、刷新、出售、冻结和合成等连续抉择。[S01] `[I]` 反复游玩动机不能仅凭功能存在推定。`[P]` 玩家可在战报中看到关键触发和伤害来源，失败后用新种子直接重开；价值是调整策略而非只看随机动画。

**故事 ST-03｜清楚知道季票买到了什么。** 代表用户：愿为更多开局试验机会付费，但反感模糊或无限续费。`[D]` 参照产品在2026季票里出售英雄选项与重掷。[S02] `[U]` 管理员希望以此变现。`[P]` 购买前显示**当前季**可选英雄数、每局重掷次数、已购季永久可玩、下一季另售、无自动续费；买完当前局若尚未锁定英雄可即时更新，否则从下一局生效。

**故事 ST-04｜断网与换机。** 代表用户：在地铁或飞行途中继续单机局的玩家。`[D]` Apple 提供购买/恢复官方路径、非消耗型购买不因时间到期。[S09][S11] `[P]` 本机进度离线保留；换机通过显式备份导入，购买权益由“恢复购买”取得而不能由备份伪造；价值是知道哪些数据可恢复、哪些依赖 Apple 网络。

## 5. 核心交互动线

每步的 `D` 是**参照品或平台确证行为**；`P` 是本产品的设计与验收目标，不能合并理解为参照品原有页面。[S01][S02][S09]

### FLOW-01 首次价值：安装到首场战斗

1. `[P]` 初装打开 `UI-01`，本地创建匿名配置及内容版本；无网络也显示“开始”。
2. `[D→P]` 参照品有英雄选择和教学 `[S01]`；本品用 `UI-02` 演示资源、上阵与战斗，再进入 `UI-03` 免费2选1。
3. `[P]` 玩家选择英雄并确认；若未选，明确提示后不能误开始。
4. `[D→P]` 参照品先招募、后自动战斗 `[S01]`；本品在 `UI-04` 给一次无惩罚指导性买入与上阵，结束准备前显示战斗预览。
5. `[P]` `UI-05` 播放或跳过结果，`UI-06` 给一条“该阵型为何胜/负”的事件；局状态持久化。终点是玩家无需账号、支付或网络即可看到自己行动的可解释反馈。

### FLOW-02 重复使用：完整轮次与重开

1. `[P]` 首页“继续”读入最近已确认快照，显示轮次、原创对手和当前规则版本；有版本迁移提示。
2. `[D→P]` 玩家买入、出售、刷新、冻结、升级、合成与摆位 `[S01]`；本品每动作原子写入快照，预算/格位不合法时保留原状态。
3. `[P]` 选择蓝图节点时必须二选一且确认；选择结果加入本局构筑而非账号永久属性。
4. `[D→P]` 自动战斗与淘汰沿用抽象循环 `[S01]`；本品 `UI-06` 展示事件和伤害计算，不隐藏 AI 额外资源。
5. `[P]` 淘汰或夺冠进 `UI-07`，可复制匿名种子、查看最近30局、更换英雄重开。保留“复盘→调整→再玩”的路径；是否带来真实回访须测试。

### FLOW-03 季票购买、离线使用、恢复与退款

1. `[D→P]` 参照品出售英雄选项/重掷 `[S02]`；本品在 `UI-03` 的“了解本季权益”进入 `UI-08`，不把购票作为开局条件。
2. `[P]` `UI-08` 读取 StoreKit 产品标识及本地化价格，清晰显示免费2选1、本季票4选1且每局1次重掷；确认后由系统支付表单处理。
3. `[D→P]` Apple有完成、恢复购买路径 `[S09]`；本品仅在 StoreKit 返回**已验证交易**后写入本季权益，交易未完成/取消/待处理均不授予。
4. `[P]` 已购本季保留可玩归档；新季独立 SKU。离线时读取系统可验证的本机交易缓存；若当前设备无可验证记录，保持免费模式并显示联网恢复入口。已锁定的当前局英雄不因权益变化重抽。
5. `[P]` 换机后点“恢复购买”，联网同步并重算季权益；出现撤销/退款交易后下次可核验时撤销未来局的高级选项，正在进行的一局保留既有英雄以免存档损坏。离线未同步的退款状态可能延迟，本品不承诺即时撤销。

### FLOW-04 存档、隐私与备份

1. `[P]` 每次合法招募动作与每轮战斗结束均原子写本机存档，前台切后台后可在下一次启动继续；正在播动画时从**已落盘的战前引擎状态**重算同一结果。
2. `[P]` 设置中“导出备份”通过系统分享单个版本化文件，文件内含局进度、历史、用户设置；明确不含 StoreKit 权益。导入先校验 schema、校验和与内容版本并给预览，确认后保留旧文件的本地回退副本。
3. `[D→P]` Apple要求如实填写自身与第三方数据收集及隐私政策 `[S12]`；本品 P0 不嵌广告/远程分析 SDK，隐私页列明本地存档、StoreKit购买处理、导出行为与支持邮箱。招募测试需用户主动选择分享本地匿名战报。
4. `[P]` 删除本机记录有二次确认；删除游戏、系统设备备份与用户自行导出的文件效果分别说明。不能承诺卸载后自动恢复本机进度。

## 6. 游戏规则与判定（均为 `[P]` 原创原型参数）

以下数字是**可实现且可测试的首版参数**，不是2019或2026《炉石》数值。数值调优须保留版本号、用户测试记录和独立创作证明。[S01]

| 规则 ID | 定义与可见反馈 | 原子失败处理 |
| --- | --- | --- |
| `GR-01` 开局 | 8席：1真人+7本机 AI。英雄池至少8名原创角色，每局按种子抽签；免费展示2名，当前季票展示4名且一次整体重掷。重掷消耗“本局机会”，不另售消耗币。 | 付费状态未验证时回退免费2选1；同一种子与权益状态生成同一候选序列。 |
| `GR-02` 资源 | 每轮给 `min(8, 3+轮次)` 点“火花”；跨轮不结转。每次买入消耗2、刷新1、卖出返回1；升级工坊档位（1—5）消耗 `3+2×当前档位`。这些数值均为实验起点。 | 余额不足时按钮禁用且不写入；卖出和升级二次确认，不能出现负值。 |
| `GR-03` 招募 | 商店每轮展示4个按当前档位权重抽得的原创单位；最多6个上阵格、2个预备格。冻结只将**未买的当前展示**带入下轮一次；刷新会先清除未冻结候选。 | 格位满时不能买入；冻结状态在下一次生成商店后清除；不可复制同一候选。 |
| `GR-04` 成长 | 拥有同一 `unitDefinitionId` 的3个基础单位可“融合”：删除3个实例，生成1个增强实例，保留来源列表；玩家从2个**本作品原创**模块中选1个加装。每轮第3、6、9轮另选1个航线蓝图，给整局一个可解释的偏转效果。 | 融合前展示将损失的强化和位置，确认后一次写入；模块候选不能是原作现成卡牌效果/文案组合。 |
| `GR-05` 布阵 | 6格分前排3、后排3。拖动仅改变索引与排位，最后一个确认版本参与战斗；后排只有当前排全空时才成为优先目标。 | 无效拖动不改变序列；“结束准备”前若为空阵容给明确确认。 |
| `GR-06` 战斗 | 对手匹配采用种子化轮转，能避免时不连续两轮碰同一 AI；存活席位为奇数时，优先让本局轮空次数最少的席位轮空，该席位本轮无胜负与生命变化，平手按种子决定。单位按“速度降序、格位升序”行动；每次在合法目标中按种子选择1个，造成攻击值伤害，生命≤0即移除；触发效果按 `行动前→命中→死亡→行动后` 固定队列结算。双方无存活单位为平局。 | 引擎有每战1000个效果事件的安全上限；超限生成可诊断错误并恢复战前快照，不能私自判负或改种子。 |
| `GR-07` 淘汰 | 玩家初始20生命。输方承受 `min(12, 轮次+胜方存活单位档位和)` 伤害；平局不伤。生命≤0淘汰；其余继续直到只剩1席，最多16轮；第16轮仍多人存活时按生命→累计胜场→种子化对决排序，明确标为“积分结束”。 | 结算只执行一次；跳动画、切后台或重启不能重复伤害。 |
| `GR-08` 公平 AI | 所有 AI 使用同一英雄/单位池、同一经济公式、同一格位与资讯范围；AI默认和免费玩家一样从2名候选中选1名，付费玩家的额外候选只改变玩家自己的选择。AI决策接口只接受当前可见快照和独立决策随机流，不能读取未来商店/战斗随机流。难度仅改变启发式，不得暗加资源。可见战报标明每次可解释行动。 | 固定种子跑批同一版本输出一致；异常 AI 决策回退合法保底动作并记本地错误。 |

**内容基线 `[P]`：** 8名英雄、40个不同的原创单位定义、12个蓝图、至少4种独创阵容主题；卡牌/角色/昵称均由原创世界观命名，且图标、画面布局、文案、声音与已知作品的组合做逐项审查。内容表须列 `definitionId`、效果文本、数值、触发时机、制作来源与授权证明。卡牌数量是制作容量假设，不是市场验证后确定的最优规模。

**内容例子 `[P]`，仅演示数据结构而非完整卡池：**“磁帆侦察艇”在己方首次刷新后给前排最低生命的友军临时护甲；“孢灯园丁”在蓝图被选择的轮次生成一个有上限的后排护盾；“旧港修补匠”在我方卖出单位后让本轮下一次升级费用减1（每轮最多1次）。正式效果、平衡与相似性均须审查；不使用原作卡牌外号作为本品实体名或营销标签。

| `SeasonProduct` | `seasonId`, `storeProductId`, `benefitVersion`, `archiveContentVersion`；每季不同非消耗型 SKU。 |

**相位状态机 `[P]`：** `home → hero_offer → recruiting → combat_prepared → combat_resolved → round_result → recruiting`；仅 `hero_offer` 可消费本局重掷，`recruiting` 可买/卖/摆位，`combat_prepared` 已锁定动作，`round_result` 只可选蓝图或继续；`eliminated/champion/cap_result` 为终态。每个合法动作先校验相位与余额、在内存得到候选新状态、原子保存后更新 UI；失败时 UI 与存档均保持旧状态。战斗由 `(seed, round, stateHash, contentVersion)` 重算，避免切后台双结算。

**版本与测试依赖 `[P]`：** 每一数值补丁更新 `balanceHash`；已开始的局沿用其创建时内容包或显示“旧版局只读/重开”，不能在半局中替换单位效果。Crash/异常事件仅存本机并在用户主动分享时附带匿名 `matchId`。用于公开测试前，应检查设备存储、后台中断、低电量、系统字体放大、VoiceOver关键按钮语义。

## 8. 季票、财务模型及发布门禁

`[P]` 首版**不采用自动续费订阅**：每个约四个月的内容季是独立非消耗型 SKU，购买后该季内容在归档中可永久玩、英雄4选1与一次重掷权益在该季归档局也继续有效；新季另售且购买前明示。旧季内容包在后续 App 版本中保留；若设备因重装尚未下载旧季包，联网取回该内容包后仍可离线玩，不将旧季权益按时间失效。这样不靠设备本地时钟判定“过期”，降低离线时间作弊与对单机订阅的信任问题。[S11] 具体在架价格以 StoreKit 展示为准，**不把商业模型里的假设68元当成已核价格**。[市场模型](../report.md#核心结论四小玩家收入和月利润的闭环测算)

**开局权益状态表 `[P]`：** `未购`＝2选1/无重掷；`本季已验证`＝4选1/本局一次；`购买待处理或取消`＝维持原状态；`曾购但本机无法验证`＝维持免费且可联网恢复；`交易被撤销`＝新局回退免费、进行中局保留既定英雄。`[D]` StoreKit提供购买恢复流程；确切交易状态实现需按目标 iOS SDK 与审核环境验证。[S09]

**发布前硬门禁 `[D→P]`：** 中国区公开发行前完成出版社/运营主体、审批号和材料路径；取得本品所有绘画、文案、音频、程序与可复用素材的权利凭证；名称/商标、整体界面与营销素材通过相似性复核；StoreKit沙盒与审核资料一致；提交真实隐私清单和公开政策。海外渠道仍需相应平台规则、税务与收款评估。[S08][S10][S12][上架报告](../../No23-iphone-indie-game-publishing-market/report.md) 这些门禁说明“何时可以发行”，不阻碍本次规格完成。

## 9. 非功能要求和测试环境

`[P]` 测试基准设备暂定 iPhone 13 与一台仍受目标 iOS 支持的较低性能设备；最低 iOS 版本在引擎选型后确定。原型目标：冷启动到首页 ≤3秒（本地内容包已解压）；普通招募动作确认到可见反馈 ≤300毫秒；战斗跳过到结果 ≤1秒；单局正常操作无内存警告；连续100局固定种子批测无不一致状态哈希或非法资源。具体预算是验收目标，性能未实测，须在实机记录 P50/P95 后调整。

`[P]` 所有对局在飞行模式可开局、继续、战斗和归档；支付/恢复必须明确提示联网而不阻断免费局。首次启动不索取跟玩法无关权限；若以后加推送、广告或分析 SDK，先更新隐私清单、用户说明及审批评估。[S12]

## 11. 已知盲点、最小验证与未决选择

1. **无拟议产品设备扫描 `[U/P]`。** 现在没有原型、实机路径、玩家访谈或真实付费数据；页面布局、时长、AI难度、单位池规模和权益价值都属设计假设。暴雪2019文章的示意画、Apple商店宣传图均不足以定位当前 iPhone 的按钮。[S01][S05][S06]
2. **权利与发行 `[D/I]`。** 原“经典卡牌＋外号＋数值＋画风”组合不能直接进入公开版。若管理员选择授权复刻支线，应取得明确授权范围，再用同一系统接口装入经许可的内容；若走原创支线，至少让独立审查者对人物轮廓、卡牌组合、数值节奏、UI 与营销识别做复核。中国区需发行/审批路径。[S08][S10]
3. **付费意愿 `[I]`。** 市场模型要求约928个同时有效的68元/四个月假设季票付费者、在2%转换假设下约4.64万月活，才达到月税前业主利润一万元；这些不是实测。[研究模型](../report.md#核心结论四小玩家收入和月利润的闭环测算) 应通过招募玩家原型测试、两季回访与实际商店沙盒外付款数据替换假设，再决定是否继续商业化。
4. **产品决策 `[P]`。** `GR-02`—`GR-07` 数值、8席长度、蓝图触发、AI难度和四个月季长须 A/B 纸面模拟与真人测试；本规格给实现基线而非证明其平衡。重点观察完成率、自发重开、7/30日回访、免费局乐趣、选择性权益付费及实际获客成本。
5. **可预期改良 `[P]`。** 透明战报、任意决策点可靠续玩、已购季永久可玩和免费完整局，是回应“单机为何季票续费”的设计方案；它们的体验优势尚未在真实用户中证实。
